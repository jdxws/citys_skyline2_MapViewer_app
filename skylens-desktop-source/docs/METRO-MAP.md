# 地铁线路图生成器

从 SKYLENS 快照生成"北京 / 上海地铁风格"的轨道交通示意图（SVG）：线路只走 0° / 45° / 90°，站距均匀，
换乘站、线路编号牌、图例俱全，并且标出河流和山（例如中央城区的梨子山）。

## 用法
```
node scripts/generate-metro-map.mjs <快照目录> [输出目录] [--seed 数字] [--font 字体名] [--mountain-name 山的名字]
```
- **快照目录**：含 `GeoJSON/`、`manifest.json`、`water-mask.png` 的文件夹。桌面版地图库里的
  `%APPDATA%\skylens-desktop\library\maps\<快照ID>` 就是；游戏导出的快照也行。
- **输出目录**：默认 `./metro-map-output`，里面有 `metro-map.svg`（矢量图，浏览器直接打开，也能导入 PPT / Word）
  和 `metro-map-layout.json`（每个站在网格上的位置，方便二次加工）。
- 需要 Node.js 20+，以及项目已安装的依赖（读取 `water-mask.png` 用到 `pngjs`，先 `npm install`）。
- 想要 PNG：用浏览器打开 SVG 另存为图片，或用 Inkscape / `rsvg-convert` 转换。
- 可以在 `package.json` 的 `scripts` 里加一行 `"metro-map": "node scripts/generate-metro-map.mjs"`，然后用
  `npm run metro-map -- <快照目录>`。

例子：
```
node scripts/generate-metro-map.mjs "%APPDATA%\skylens-desktop\library\maps\c4653fee929a085b" out --mountain-name 梨子山
```

## 它是怎么做的
1. **去掉重复的站**：游戏导出的每条线路都是"去程 + 回程"的闭合走向，同一个站会出现两次（两个方向各一个站台）。
   这里按站名合并，所以 1/2/3/6 号线各画成一条线，两端是终点站。用导出里的 `Stop` 数做校验
   （线性线路 = 2×站数 − 2，环线 = 站数），对不上会在运行时提示。
2. **环线**：内环、外环站点相同、方向相反，合并成一条环线，编号牌写 `4/5`。
3. **换乘站**：同名站点属于多条线路，画成大圆圈。
4. **示意化排布**：在网格上做模拟退火，让每个区间尽量是 0° / 45° / 90°、站距均匀、少转弯、线路不交叉，
   同时尽量保持大致的东南西北关系。站间距和方位**不按实际比例**。
5. **河流**：来自 `water-mask.png`。提取轮廓后，用薄板样条形变带着河流跟站点一起移动，
   所以"线路过不过河"和实际一致；河中的岛屿按奇偶规则挖空。
6. **山**：在城区里找"被建筑和道路包围的圆形空地"（半径 ≥ 450 米，周围一圈 ≥ 70% 被占用，河面不算），
   当作山来画。找不到就不画。山的名字用 `--mountain-name` 指定（默认"梨子山"）。

## 自检
每次运行都会打印一行自检结果：非八方向的区间数、线路交叉数、最小站距、过河关系不一致的区间数、
有没有站点落在山里。正常应是前两项为 0。

## 调整
- 布局不满意：换一个 `--seed`（不同的随机种子会排出不同的版式）。
- 颜色、线宽、站点间距、退火次数都在脚本顶部的 `CONFIG` 里。默认使用游戏里的线路颜色，
  只把 3 号线的黄色和环线的灰色调深了一点（`colorOverrides`），方便在白底上看清。
- 字体：默认 `Microsoft YaHei / PingFang SC / Noto Sans CJK SC`，缺字体时用 `--font` 指定。

## 已知限制
- 目前只画地铁（`Transport = Subway`）；火车、轮渡等没有画。
- 水体只用于画河流和校验过河关系；示意图里的河流是平滑后的形状，不是精确岸线。
- 山的识别是启发式的（城区里被包围的圆形空地），如果城里有别的大片空地也满足条件，选分数最高的那一个。

## 测试
`npm test` 会运行 `test/metro-map.test.js`（线路去重与环线合并、换乘站、八方向连线、排布不交叉、
行进方块法与奇偶规则、样条形变、SVG 输出）。设置环境变量 `SKYLENS_SNAPSHOT` 指向快照目录，
还会额外跑一遍完整流程。
